- **Budgettabelle (CR-E101c-V08):** neue Datei `docs/wap-planer/perf/budgets.json`, Schwellwert nach Prompt §7. Der **test-engineer legt sie in Schritt 3 an**, wörtlich nach dieser Tabelle (ADR-010 §8). Sie wird **beim Freeze in Schritt 6 gesperrt**; der implementer (Codex) liest sie nur. Eine Änderung ist nur mit `lock-update` und Zustimmung des Auftraggebers zulässig. Inhalt wörtlich:

  ```json
  { "version": 1, "quelle": "ADR-010 §8, Prompt §7, Beschrieb 11",
    "budgets": [
      { "anforderung": "R-11-11", "endung": "Bildzeit", "budgetMs": 16.7 },
      { "anforderung": "R-11-11", "endung": "Aufgabe", "budgetMs": 50 },
      { "anforderung": "R-11-12", "budgetMs": 300 },
      { "anforderung": "R-11-14", "budgetMs": 500 },
      { "anforderung": "R-11-15", "budgetMs": 3000 },
      { "anforderung": "R-11-16", "budgetMs": 10000 },
      { "anforderung": "R-11-17", "budgetMs": 15000 } ] }
  ```

  - **Schema (CR-E101c-V22).** Ungültig ist die Datei, wenn eine Regel verletzt ist:
    - `version` ist nicht 1;
    - `budgets` ist kein nicht leeres Array;
    - `anforderung` passt nicht auf `^R-[0-9A-Z.]+-\d{2}$`;
    - `budgetMs` ist nicht endlich oder ≤ 0;
    - `endung` ist gesetzt und leer bzw. kein Text;
    - ein Paar (`anforderung`, `endung`) kommt doppelt vor;
    - eine Anforderung hat Einträge mit und ohne `endung` oder mehr als einen ohne `endung`.

    Ungültig → `comparePerf` rot «budgets.json ungültig: <Regel>»; `registerPerfEntries` und `recordMetric` werfen dieselbe Meldung.
  - **Passender Eintrag:** gleiche `anforderung` und, falls gesetzt, `name` endet auf `endung`. Es muss genau ein Eintrag passen, und `budgetMs` muss ihm **gleich** sein.
  - **Sonst:** «Budget nicht nach ADR-010 §8: <name>». Dazu gehören eine unbekannte Anforderung (z.B. R-11-13 vor Etappe 2), ein abweichender Wert und bei R-11-11 ein Name ohne die Endung `Bildzeit` bzw. `Aufgabe`.
  - **Geprüft** in `registerPerfEntries` (wirft; statischer JSON-Import), `recordMetric` (wirft) und `comparePerf` (rot).
- **`registerPerfEntries`** wirft «Leistungseintrag ungültig: <name>» bei:
  - `name` nicht `^[A-Za-z][A-Za-z0-9]*$`;
  - `anforderung` nicht `^R-[0-9A-Z.]+-\d{2}$`;
  - `budgetMs` nicht nach der Budgettabelle.

  Doppelter Name, auch über Dateien hinweg → «Leistungseintrag doppelt: <name>».
- **`registrierteEintraege`:** Einträge ohne Funktionen, sortiert nach `name`.
- **`messeEintrag(name, seed)`:**
  - `p = await prepare(seed)`, dann `performance.now()` vor und nach `await run(p)`; Ergebnis ist die Differenz in ms.
  - Unbekannter Name → Ablehnung «Leistungseintrag unbekannt: <name>».
  - `run` endet erst im fertigen Zustand; das ist Pflicht der Eintragsdatei.
- **Harness-Einstieg** `tests/wap-perf/harness/index.ts` (neu, Umsetzung; CR-E101c-V13):
  1. `const module = import.meta.glob('./entries/*.ts')` (nicht eager).
  2. Jede Datei in alphabetischer Reihenfolge nacheinander mit `await module[pfad]()` laden, in `try`/`catch`, **innerhalb einer asynchronen Funktion**, die am Ende des Moduls aufgerufen wird. Kein Top-level-`await`: Vite meldet dafür im IIFE-Format «Top-level await is currently not supported» (CR-E101c-V23). So wird eine werfende Eintragsdatei abgefangen, bevor die Seite «bereit» meldet.
  3. Wirft eine Datei: `document.documentElement.dataset.wapPerf = 'fehler'`, kein `__wapPerf`.
  4. Sonst `globalThis.__wapPerf = { eintraege: registrierteEintraege, messe: messeEintrag }` und `dataset.wapPerf = 'bereit'`.

### 2.4 Offline-Hilfe (R-H-25; CR-E101c-V09)

```ts
// tests/wap-e2e/support/fixtures.ts (Rückgabetyp gegenüber dem gesperrten Stub erweitert; Anpassung in Schritt 7)
export interface OfflineHilfe {
  readonly context: BrowserContext;          // Getter: immer der zuletzt gestartete Kontext
  readonly abgebrochen: readonly string[];   // URLs abgebrochener HTTP-Anfragen und WebSockets aller Starts, in Reihenfolge
  restart(): Promise<BrowserContext>;        // schliesst den aktuellen Kontext, startet neu, liefert den neuen
  close(): Promise<void>;                    // schliesst den aktuellen Kontext; löscht nichts
}

```

- **Prüfung (Datenschutz; nur beim Aufruf von `offlinePersistent`, nicht bei `restart()`, das bewusst dasselbe gefüllte Profil verwendet):** `realpath` des vorhandenen Elternordners von `userDataDir` muss unter `realpath(os.tmpdir())` oder unter `realpath(<process.cwd()>/test-results)` liegen; beide Seiten werden aufgelöst (8.3-Kurznamen, Junctions; CR-E101c-V24). Der Ordner darf noch nicht bestehen oder muss leer sein. Sonst wirft die Hilfe «offlinePersistent: userDataDir muss neu und unter dem Temp-Ordner oder test-results liegen», ohne Start. So kann kein bestehendes Browserprofil geöffnet werden.
- **Start:** `chromium.launchPersistentContext(userDataDir, …)` aus `@playwright/test` mit:
  - `channel: 'msedge'`, `headless: true`, `acceptDownloads: true`;
  - `downloadsPath: <userDataDir>.downloads` (gleiche Regel wie oben);
  - 1600×1000, Skalierung 1, `locale: 'de-CH'`, `timezoneId: 'Europe/Zurich'`.
- **Netz gesperrt und protokolliert** in jedem Start:
  - `context.setOffline(true)`;
  - `context.route(u => !['file:', 'data:', 'blob:'].includes(u.protocol), r => { abgebrochen.push(r.request().url()); return r.abort('internetdisconnected'); })`;
  - `context.routeWebSocket(() => true, ws => { abgebrochen.push(ws.url()); ws.close(); })`.
  - Ein Filter ohne Ausnahme für `file:` bricht die Navigation zur lokalen Datei ab (Spike §8).
  - Die URLs werden nie ausgegeben, nur zurückgegeben.
- **Fehler:** Ein Startfehler wird als «offlinePersistent: Start gescheitert: <Meldung>» weitergegeben.
- **Aufräumen:** Die Hilfe löscht weder Profil noch Download-Ordner. Der Aufrufer schliesst den Kontext und löscht beide Ordner im `finally`.

### 2.5 Barrierefreiheit (R-H-26, nur Fixtures)

- **`a11y(scope?)`:** wie Vertrag E1-01 §9 Nr 11 (`@axe-core/playwright`, Tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`). Funktioniert auch unter strikter CSP (Spike §8).
- **`focusVisible(locator)` → `{ sichtbar, kontrast }`:**
  1. `scrollIntoViewIfNeeded`. Ausschnitt = Rahmen des Elements, je Seite um 8 px erweitert und auf den Viewport begrenzt.
  2. Zustand A: Element verlassen (`blur`); `document.activeElement` ≠ Element.
  3. Zustand B: `keyboard.press('Shift')`, dann `locator.focus()`. Ist `document.activeElement` danach nicht das Element, wirft die Hilfe «focusVisible: Element nicht fokussierbar».
  4. Je Zustand `page.screenshot({ clip, animations: 'disabled', caret: 'hide', scale: 'css' })`, dekodiert mit `@napi-rs/canvas`.
  5. Geändert = Pixel mit einem RGB-Unterschied zwischen A und B. P = 2 · (Breite + Höhe) des Elements in CSS-px, gerundet.
  6. `sichtbar` = Anzahl geänderter Pixel ≥ P.
  7. `kontrast` = grösstes k, das mindestens P geänderte Pixel erreichen. Gemessen wird der Kontrast nach WCAG 2.x (relative Luminanz, (L1 + 0,05)/(L2 + 0,05)) zwischen B und A am selben Pixel. Weniger als P geänderte Pixel → 1. Abgerundet auf 2 Dezimalen.

### 2.6 Rot-Phase bei Playwright-Meldungen (R-H-35, E1-01-31)

`fachlichRot` (red-phase.mjs) gilt **zusätzlich** als fachlich rot, wenn alle Bedingungen gelten (Zeilen nach `ohneFarben`, an `\n` getrennt):
1. Zeile 1 beginnt mit `Error: `.
2. Es gibt eine Zeile k ≥ 3, deren Vorgänger leer ist (nach `trimEnd`) und die auf `^expect\([A-Za-z]+\)(\.not)?\.[A-Za-z]+\(` passt.
3. Vor Zeile k steht keine Zeile eines Codeausschnitts (`^\s*>?\s*\d+ \|`).

- Bestehende Zweige von `fachlichRot` bleiben unverändert, ebenso fast-check und die Stubs.
- Gemessene Formen (§8): `toBe`, `toEqual`, `.not`, `expect.soft`, `expect.poll` mit `message`, Locator-Matcher mit Wartezeit, `toPass`, mehrzeilige Meldung.
- Nicht fachlich rot bleiben:
  - `Error: <Text>` ohne solche Zeile (auch mit «Expected/Received»-Zeilen);
  - eine `expect(`-Zeile ohne Leerzeile davor oder erst nach einem Codeausschnitt;
  - `TypeError`;
  - `toPass` oder `expect.poll` (mit und ohne Meldung) um einen inneren `TypeError` oder einen fremden Stub (Spike des Reviewers, g01–g07).
- **Restrisiko** (wie die bestehende Regel `^Error: expect\(`): Ein Test, der einen solchen Text selbst wirft, gilt als fachlich rot. Der `test-reviewer` prüft das.
