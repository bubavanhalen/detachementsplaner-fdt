## 1 Seitenmodell (`src/model/wap/layout/pageModel.ts`) – Schnittstelle Layout → Zeichner

Vollständig (nur Typen und eine Konstante, kein Stub). Masse in pt, Ursprung oben links, y nach unten.

```ts
import type { Id, Rgb } from '../types';
import type { FontWeight } from './text/types';   // AR0-11

export interface Rect { readonly x: number; readonly y: number; readonly w: number; readonly h: number }
/** widthPt endlich > 0, mittig auf der Kante; dash in pt (≥ 1 Wert, jeder endlich > 0, Phase 0), null = durchgezogen; Enden stumpf, Ecken spitz. */
export interface Stroke { readonly color: Rgb; readonly widthPt: number; readonly dash: readonly number[] | null }
export type ItemRole =
  | 'header' | 'frame' | 'timeAxis' | 'gridLine' | 'dayHeader' | 'columnHeader' | 'band'
  | 'block' | 'querbalken' | 'marker' | 'rapport' | 'besoBox' | 'agenda' | 'sidebar' | 'legend' | 'signature' | 'sun' | 'continuation';
interface ItemBase { readonly role: ItemRole; readonly entryId?: Id }
/** fill und stroke null → nichts gezeichnet. */
export interface RectItem extends ItemBase { readonly kind: 'rect'; readonly rect: Rect; readonly fill: Rgb | null; readonly stroke: Stroke | null }
export interface LineItem extends ItemBase { readonly kind: 'line'; readonly x1: number; readonly y1: number; readonly x2: number; readonly y2: number; readonly stroke: Stroke }
/** SVG-Syntax, nur absolute Befehle M, L, C, Z, Zahlen in pt (y nach unten); Füllregel nonzero. */
export interface PathItem extends ItemBase { readonly kind: 'path'; readonly d: string; readonly fill: Rgb | null; readonly stroke: Stroke | null }
export interface TextRunOut { readonly text: string; readonly weight: FontWeight; readonly color: Rgb; readonly strike: boolean }
/** Eine vorberechnete Zeile. x/baselineY = Beginn der Grundlinie vor der Drehung; rotation 90 = von unten nach oben lesbar, 270 = von oben nach unten. Läufe folgen ohne Abstand (Vorschub je Lauf = measureRuns([lauf], sizePt)). */
export interface TextItem extends ItemBase {
  readonly kind: 'text'; readonly x: number; readonly baselineY: number; readonly rotation: 0 | 90 | 270;
  readonly sizePt: number; readonly runs: readonly TextRunOut[];
  readonly frame: Rect;                                    // Rahmen für die Ebene-2-Prüfung; nicht gezeichnet
}
/** Nur Unterschrift (E1-10); einziges Rasterelement. */
export interface ImageItem extends ItemBase { readonly kind: 'image'; readonly rect: Rect; readonly mime: 'image/png' | 'image/jpeg'; readonly bytes: Uint8Array }
export type PageItem = RectItem | LineItem | PathItem | TextItem | ImageItem;
/** Zeichenreihenfolge = Reihenfolge in `items` (spätere liegen oben). */
export interface PageModel { readonly widthPt: number; readonly heightPt: number; readonly kind: 'week' | 'continuation'; readonly items: readonly PageItem[] }
/** Durchstreichung in em aus OS/2 von Arimo (unitsPerEm 2048): Mitte (530 − 102/2) / 2048 über der Grundlinie, Dicke 102 / 2048. */
export const STRIKE_EM: { readonly center: number; readonly thickness: number };   // { center: 479/2048, thickness: 102/2048 }
```

Jede über den Adapter erzeugte Schrift: `layout(text, features)` liefert je Codepunkt genau `glyphForCodePoint(codePoint)` (cmap; .notdef bei fehlender Glyphe), `features` wird nicht ausgewertet (kein GSUB, kein GPOS, kein Kerning); `createSubset()` liefert die Teilmenge von fontkit 2 mit zusätzlichem `encodeStream()`, das nach dem Anmelden der Empfänger genau einmal `'data'` mit den Bytes von `encode()` und danach `'end'` meldet, bzw. `'error'`, wenn `encode()` wirft; alle übrigen Felder unverändert. Das übergebene Modul bleibt unverändert; kein Zufall, keine Uhr.

### 2.3 Regeln für `writePdf` (verbindlich)

1. **Seiten (R-10-01):** je `PageModel` eine Seite in Reihenfolge von `pages`, MediaBox `[0 0 widthPt heightPt]` exakt, kein `/Rotate`, keine weiteren Boxen. Umrechnung: PDF-x = x, PDF-y = `heightPt` − y.
2. **Reihenfolge:** Elemente in der Reihenfolge von `items`; ein `RectItem`/`PathItem` mit Fläche und Rahmen ist ein Malvorgang (Füllen, dann Strich).
3. **Vektoren:** `RectItem`, `LineItem`, `PathItem` als Pfade; Farbe DeviceRGB `r/255, g/255, b/255`; Strich nach `Stroke` (Breite, Strichelung mit Phase 0, Enden stumpf, Ecken spitz), Füllregel nonzero. **Keine skalierte CTM** (TR-E101b-10): erlaubt sind nur Verschiebung, Spiegelung der y-Achse bei Pfaden (Matrix `[1 0 0 −1 tx ty]`) und Drehung bei Text; |det| der CTM ist bei jedem Strich 1, sodass `readPdf` `widthPt` und `dash` unverändert liest.
4. **Text (R-10-05):** jeder Lauf eines `TextItem` als eigene Textanzeige (Schnitt, `sizePt`, Farbe, Drehung 0/90/270 um `(x, baselineY)`), Text Codepunkt für Codepunkt unverändert, Glyphen über den Adapter (cmap, ohne Kerning, ohne Ersetzung), keine Zeichen- und Wortabstände (`Tc`, `Tw` 0, `Tz` 100). Lauf k beginnt um Σ `measureRuns([lauf_i], sizePt)` (i < k) in Leserichtung versetzt. Läufe mit leerem Text werden nicht gezeichnet. Kein Text als Pfad oder Bild.
5. **Durchstreichung** (`strike: true`, V-02c-2): eine Linie in Laufbreite, parallel zur Grundlinie im Abstand `STRIKE_EM.center × sizePt` auf der Oberlängenseite, Breite `STRIKE_EM.thickness × sizePt`, Farbe des Laufs, durchgezogen; gezeichnet unmittelbar nach dem Lauf.
6. **Schriften (R-10-36):** Arimo Regular bzw. Bold aus `fontBytes` (E1-02b), je verwendetem Schnitt genau eine Schrift als **Teilmenge** (`subset: true`), Type0/CIDFontType2 mit `FontFile2` und `ToUnicode`; ein Schnitt ohne Lauf wird nicht eingebettet. Name `<TAG>+Arimo` bzw. `<TAG>+Arimo-Bold`; `<TAG>` = sechs Buchstaben A–Z aus der Menge der Codepunkte aller gezeichneten Läufe dieses Schnitts im Dokument: `h = 0x811C9DC5`; für jeden Codepunkt aufsteigend, ohne Doppelte, für jedes der Bytes `(cp >> 16) & 0xFF`, `(cp >> 8) & 0xFF`, `cp & 0xFF`: `h = Math.imul(h ^ byte, 0x01000193) >>> 0`; dann sechsmal `Buchstabe = 'A' + (h % 26)`, `h = Math.floor(h / 26)`. Der Name hängt also nur von der Zeichenmenge ab, nicht von Reihenfolge oder Anzahl. fontkit wird im ersten Aufruf mit `import('fontkit')` geladen (ADR-001, ADR-005 Punkt 2).
7. **Metadaten und Determinismus (R-L-01):** `PDFDocument.create({ updateMetadata: false })`; das Info-Wörterbuch enthält nur `Title` = `input.title`, `Producer` und `Creator` = «WAP-Planer»; kein `CreationDate`, kein `ModDate`, kein `/ID`, kein XMP; Speichern mit `useObjectStreams: false`. Gleiche Eingabe ergibt dieselben Bytes: zweimal im selben Prozess, in zwei Prozessen, in verschiedenen Zeitzonen, in Node und in Edge. Kein Zufall, keine Uhr, keine Abhängigkeit von Objektidentität.
8. **Bilder:** `ImageItem` nach `mime` eingebettet und in `rect` gezeichnet; sonst keine Rasterbilder.

### 2.4 Fehlerverhalten

`writePdf` prüft die ganze Eingabe, bevor es eine Schrift lädt oder zeichnet: zuerst `pages` leer, dann je Seite in Reihenfolge die Seitengrösse und die Elemente in Reihenfolge, je Element zuerst `invalidItem`, dann `missingGlyph`. Beim ersten Verstoss lehnt es mit `PdfWriteError` ab; Fundstelle in `pageIndex`/`itemIndex` (0-basiert).

| Code | Fall | Meldung (Vorschlag Meldungskatalog E1-11) |
| --- | --- | --- |
| `invalidItem` | `pages` leer (`pageIndex` null); Seitengrösse nicht endlich oder ≤ 0; eine gezeichnete Zahl nicht endlich (Koordinaten, `rect`, `sizePt`, `widthPt`, `dash`); `rect.w`/`rect.h` < 0; `sizePt` ≤ 0; `widthPt` ≤ 0; `dash` leer oder mit Wert ≤ 0; `Rgb` nicht ganzzahlig 0–255; `d` mit anderem Befehl als M, L, C, Z oder falscher Zahlenzahl; Bild nicht lesbar; unbekannte `kind`; Codepunkt U+0000–U+001F, U+007F–U+009F, U+2028 oder U+2029 in einem Lauf | Ursache «Das PDF konnte nicht erzeugt werden, weil ein Element der Seite ungültig ist.» (Text nach V07) · nächster Schritt «Den WAP-Planer neu laden und das PDF erneut erzeugen. Bleibt der Fehler, die zuletzt geänderten Einträge prüfen.» |
| `missingGlyph` | Codepunkt eines Laufs ohne Glyphe im Schnitt des Laufs (`fontMetrics().advance(cp, weight) === null`); `character` = erstes solches Zeichen (V-02c-1) | Ursache «Der Plan enthält das Zeichen «‹z›» (U+XXXX), das die Schrift des WAP-Planers nicht darstellen kann.» · nächster Schritt «Das Zeichen im betroffenen Eintrag ersetzen und das PDF erneut erzeugen.» |
| `fontLoad` | `import('fontkit')` scheitert, oder fontkit/pdf-lib können die Schriftbytes nicht lesen (`cause` = Originalfehler; `pageIndex`/`itemIndex` null); prüfbar mit `vi.mock` des öffentlichen Moduls `src/assets/wap-fonts/index.ts` (E1-02b) | Ursache «Die Schrift für das PDF konnte nicht geladen werden.» · nächster Schritt «Seite neu laden. Bleibt der Fehler, die Datei des WAP-Planers neu herunterladen.» |

Nicht geprüft und kein Fehler: `frame`, `role`, `entryId`, Elemente ausserhalb der Seite, Schriftgrösse unter 4,5 pt (Ebene-2-Prüfung und P8, nicht Sache des Schreibers). Keine Konsolenausgabe.

### 3.2 Seite (`PageView.tsx`, `pageView.css`)

```tsx
export interface PageViewProps {
  readonly page: PageModel;
  readonly scale: number;                  // px pro pt (Zoom), endlich > 0; Umbrüche bleiben unverändert (R-5-02)
  readonly label: string;                  // zugänglicher Name, z.B. «Wochenseite KVK»
  readonly overlay?: ReactNode;            // Bedien- und Prüfmarken, nur Bildschirm (R-5-03)
  readonly semanticsProvidedByOverlay?: boolean;   // true: Papier aria-hidden (E1-12); Standard false
}
export function PageView(props: PageViewProps): JSX.Element;
```

Darstellung (verbindlich, R-L-04):

- **Container** `div` mit `role="document"`, `aria-label={label}`, Grösse `widthPt × scale` × `heightPt × scale` px, `position: relative`, `overflow: hidden`.
- **Papier** (erstes Kind): `widthPt × 4` × `heightPt × 4` px, `transform: scale(scale / 4)`, `transform-origin: 0 0` (feste Auflösung 4 px pro pt, ADR-004 Punkt 4, AR0-13 b); `aria-hidden="true"` nur bei `semanticsProvidedByOverlay`.
- **Reihenfolge wie `items`:** Jede ununterbrochene Folge von Nicht-Text-Elementen ist ein eigenes `svg` (`aria-hidden="true"`, `viewBox="0 0 widthPt heightPt"`, Seitengrösse, `position: absolute`, `pointer-events: none`) mit den Formen in Reihenfolge; Strich, Strichelung, Enden, Ecken und Füllregel wie 2.3 Nr 3; Bild als `<image>` mit `data:`-URL.
- **Zeile:** Jedes `TextItem` ist genau **ein** `span` mit `data-wap-item="<Index in items>"`, `position: absolute`, `white-space: pre`, `font-family: 'WAP Arimo'`, `font-kerning: none`, `font-variant-ligatures: none`, `font-synthesis: none`, `font-size` = `sizePt × 4` px, Grundlinienbeginn bei `(x, baselineY)`, Drehung per CSS-Transform um diesen Punkt (90 → `rotate(-90deg)`, 270 → `rotate(90deg)`). Darin je Lauf ein `span` (`font-weight` 400/700, Farbe, Text); `textContent` der Zeile = Verkettung der Lauftexte. Text bleibt markierbar.
- **Durchstreichung** je durchgestrichenem Lauf als leeres `span` mit `aria-hidden="true"` in der Zeile, Lage und Dicke wie 2.3 Nr 5 (nicht `text-decoration`, dessen Lage browserabhängig ist).
- **Overlay** als letztes Kind des Containers, ausserhalb des Papiers (Koordinaten in px der Zoomstufe).
- **Laden:** Bis `ensureScreenFont` erfüllt ist, enthält der Container kein Papier und trägt `aria-busy="true"` (V-02c-4); nie Text in Ersatzschrift.
- **Lagetoleranz** gegen das Seitenmodell (in Edge gemessen, Grundlinie über einen Null-Marker `vertical-align: baseline` wie im Spike ADR-004): x und Zeilenbreite (= `measureRuns(runs, sizePt)`) ± 0,05 pt, Grundlinie ± 0,15 pt (0,6 px bei 4 px/pt), bei `scale` 1 und 2.

## 6 Präzisierungen in Prompt §5.2 Schritt 2 (architect, 04.10.2026)

Grund aller Punkte: Abgleich mit den gemergten Paketen E1-02a (`types.ts`, `errors.ts`) und E1-02b (`FontWeight`, `FONT_FAMILY_SCREEN`, `fontBytes`, `measureRuns`, `fontMetrics`) und mit E1-01b (`readPdf`, `pdfArtefakt`, Playwright-Projekte); eindeutige Erwartungen für die Tests der 6 IDs; Tragfähigkeit für E1-02d, -02e, -02f, -05, -10, -12, -16.

- **P-1 Seitenmodell** ergänzt um Strich-Semantik, Pfad-Grammatik (M, L, C, Z absolut), Lauffolge und `STRIKE_EM`: Bildschirm (SVG) und PDF zeichnen nur dann gleich, wenn diese Festlegungen für beide gelten. `ImageItem` bleibt (Unterschrift, Vertrag E1-10).
- **P-2 `createFontkitAdapter(fontkit)`** statt `()`, Rückgabe `PdfLibFontkit` statt `unknown`: fontkit wird erst in `writePdf` geladen (ADR-001), der Adapter ist mit dem echten Modul testbar.
- **P-3 Adapter-`layout` je Codepunkt über die cmap.** Spike (Abschnitt 7): fontkit-`layout` ersetzt 27 unsichtbare Codepunkte (U+034F, U+200B–U+200F, U+202A–U+202E, U+2060–U+2064, U+2066–U+206F, U+FEFF) durch die Leerzeichen-Glyphe; die PDF-Breite weicht dann von `measureRuns` ab (Probe 23,3447 statt 21,9556 pt). Mit cmap-`layout` 0 Abweichung. Präzisiert ADR-004 Punkt 2 («ohne Kerning, keine Ligaturen») und den Adapter von ADR-005 Option B; kein Konflikt mit dem ADR.
- **P-4 `src/io/wap-pdf/fontkit.d.ts`** (Typen der genutzten fontkit-Schnittstelle; Besitz E1-02c, wie `hyphen.d.ts` in E1-02b).
- **P-5 Teilmenge (Befund E1-01b-03).** Ursache des Befunds: fontkit 2 ohne Adapter (`_this.subset.encodeStream is not a function`, im Spike reproduziert). Mit Adapter gelingt die Teilmengen-Einbettung; `readPdf` liest Text, Grössen, Breiten und Metriken (`ascent > 0 ≥ descent`). ADR-005 Punkt 3 (Teilmenge) bleibt; ganze Schrift nur als Rückfall (470 393 statt 10 241 Byte, und zwar in jedem Stand-PDF).
- **P-6 Teilmengen-Präfix** mit festem Algorithmus (2.3 Nr 6): ADR-005 Punkt 3 «aus der Glyphenmenge abgeleitet»; rein, synchron, in Node und Edge gleich (ohne `crypto.subtle`). pdf-lib setzte sonst ein Suffix aus einem Zufallsgenerator mit fester Saat je Dokument.
- **P-7 Fehler:** `missingGlyph` neu, `invalidItem` abschliessend aufgezählt, Fundstelle `pageIndex`/`itemIndex`/`character`, Prüfreihenfolge festgelegt. Grund: In der Teilmenge fehlt die Breite von .notdef (CID 0 nicht in `/W`, Standardbreite 1000 statt 1536/2048 em; Probe 25,8423 statt 24,5923 pt), Text wäre breiter als gemessen. Steuerzeichen und U+2028/U+2029 trennt bzw. ersetzt pdf-lib in `drawText`.
- **P-8 Metadaten und Speicherform** abschliessend (2.3 Nr 7), dazu `useObjectStreams: false` und kein `/Rotate`: eindeutige Bytes für R-L-01 und für Stand-PDF (ADR-005 Punkt 4).
- **P-9 Keine skalierte CTM (TR-E101b-10).** Spike: `readPdf` liest 0,48 / 0,96 / 0,72 pt für Rechteck, Linie und Pfad (pdf-lib `drawSvgPath` mit Spiegelung, |det| = 1) exakt. Solange 2.3 Nr 3 gilt, braucht `readPdf` keine Änderung; Vorschlag: TR-E101b-10 schliessen.
- **P-10 Ablage für V5-ebene2 (Befund E1-01b-02):** Jeder Test, der mit `writePdf` ein gültiges PDF erzeugt, legt es mit `pdfArtefakt('e1-02c-<fall>', bytes)` ab (Name nach `/^[a-z0-9][a-z0-9-]{0,79}$/`), auch die in Edge erzeugten Bytes (Node-Seite des Playwright-Tests). Ausgenommen sind nur PDF, die absichtlich Text unter 4,5 pt enthalten.
- **P-11 Durchstreichung** am Bildschirm als eigenes Element, im PDF als Linie, beide aus `STRIKE_EM` (V-02c-2).
