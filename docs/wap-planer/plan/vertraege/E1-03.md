## 1 Befehlsform (`command.ts`)

```ts
import type { Draft, Patch } from 'immer';
export interface CommandContext { readonly templates: TemplateSet }
export interface CommandResult {
  readonly plan: Plan; readonly patches: readonly Patch[]; readonly inversePatches: readonly Patch[];
  readonly label: string; readonly affectedDates: readonly IsoDate[]; readonly affectedEntryIds: readonly Id[];
}
export interface CommandTools { newId(prefix: IdPrefix): Id; newSeq(): number }
export type NumberingPolicy = 'auto' | 'none';
export interface CommandOptions { readonly numbering?: NumberingPolicy }          // Standard 'auto'
export type CommandErrorCode = 'notFound' | 'wrongEntryType' | 'invalidEntry' | 'besoWithoutWindow' | 'invalidPlacement' | 'invalidTime' | 'invalidDate' | 'outsidePlan' | 'lastTimeWindow' | 'unknownWeek' | 'unknownColumnSet' | 'unknownColumn' | 'invalidColumnSet' | 'emptySelection' | 'invalidNumber' | 'numberTaken';
export interface CommandErrorDetails { readonly field?: string; readonly entryId?: Id }
export class CommandError<C extends string = CommandErrorCode> extends WapError {
  declare readonly code: C; readonly field: string | null; readonly entryId: Id | null;
  constructor(code: C, userMessage: UserMessage, details?: CommandErrorDetails, options?: { cause?: unknown });
}
export function command(plan: Plan, label: string, recipe: (draft: Draft<Plan>, tools: CommandTools) => void, ctx: CommandContext, options?: CommandOptions): CommandResult;
```

**1a Ablauf von `command`** (gilt für jeden Befehl dieses und späterer Pakete):
1. `recipe` läuft auf dem Entwurf (`produceWithPatches`). `tools.newId(p)` = `p + draft.nextId`, danach `draft.nextId + 1` (gleiche Formel wie `allocateIds`, E1-02a P-3); `tools.newSeq()` gibt `draft.nextSeq` zurück und erhöht ihn. Beide Zähler sind damit Teil der Patches; Undo stellt sie exakt her (AR0-41).
2. Jeder Eintrag, den das Rezept hinzufügt oder ändert, wird geprüft, in Eingabereihenfolge des Befehls (bei direktem Aufruf von `command`: Reihenfolge der ersten Änderung im Rezept): (a) `validateEntry(planDanach, e)` – der erste Befund wird `CommandError` mit `field` = Befundfeld, `entryId`; Code `invalidPlacement` bzw. `besoWithoutWindow` bei diesen Befundcodes, sonst `invalidEntry`; (b) Plan-Bereich: Block, Marker, Rapport, Beso und Ganztägige Bemerkung müssen mit `date` in einer Woche des Plans liegen, Querbalken und Bemerkung mit Zeitraum mit mindestens einem Tag, sonst `outsidePlan` (`field` `date`, `fromDate` bzw. `scope`). Nur durch die Nummerierung berührte Einträge werden nicht geprüft.
3. Bei `numbering` `'auto'`: jedes Datum, an dem das Rezept einen Beso hinzufügt, entfernt oder ändert (Datum vorher und nachher), wird aufsteigend mit `assignNumbers(…, 'auto')` nummeriert (Abschnitt 3); abweichende `besoNumber` werden gesetzt. Bei `'none'` bleibt jede Nummer, wie das Rezept sie hinterlässt.
4. Ergebnis: `applyPatches(plan, patches)` ist strukturell gleich `result.plan`, `applyPatches(result.plan, inversePatches)` strukturell gleich `plan`. Ein Befehl ist genau ein Undo-Schritt (Beschrieb 5.6 Punkt 6). Felder werden nur geschrieben, wenn sich ihr Wert strukturell ändert; ohne Wirkung gilt `result.plan === plan` und `patches`, `inversePatches`, `affectedDates`, `affectedEntryIds` sind leer (die Oberfläche committet dann nichts, E1-11).
5. Fehler: Das Rezept oder Schritt 2 wirft `CommandError`; der Plan bleibt unverändert (rein). Andere Ausnahmen sind Programmfehler und werden nicht umgedeutet (`_konventionen.md` §3).

**1b Betroffenes.** `affectedEntryIds`: hinzugefügte, geänderte (auch nur durch die Nummerierung) und entfernte Einträge, ohne Doppel, sortiert wie `Array.prototype.sort()`. `affectedDates`: aufsteigend, ohne Doppel, Vereinigung über diese Einträge im Zustand vorher und nachher: Block, Marker, Rapport, Beso, Ganztägige Bemerkung → `date` und zusätzlich `date + 1`, wenn eine Zeit `range` mit `to > 1440` vorkommt; Querbalken → jedes Datum `fromDate … toDate`; Mehrtägige Bemerkung → `range` jedes Datum, `week` die sieben Daten der Woche, `plan` alle Daten aller Wochen; dazu je geänderter `DayConfig` ihr Datum und je geändertem Spaltensatz die Daten aller Tage, die ihn vorher oder nachher verwenden. Andere Änderungen tragen keine Daten bei.

**1c Bezeichnung (`label`)**, Deutsch (UI-Richtlinie 3, «Rückgängig: ‹label›»). Typname: Block, Querbalken, Marker, Rapport, Beso, Ganztägige Bemerkung, Bemerkung. Kurztext K: Titel (`resolveTitle`, Text der Läufe, am Rand getrimmt), Rapport `code`, Marker `markerLabel`, Bemerkungen `text`; über 40 Zeichen (Codepunkte) auf 40 gekürzt plus «…». Ein Eintrag: «‹Typ› «‹K›» ‹Verb›», bei leerem K ohne ««‹K›»» (gilt für alle Muster); mehrere: «‹n› Einträge ‹Verb›». Verben: `createEntry` erstellt, `updateEntry`/`updateEntries` geändert, `moveEntries` verschoben, `deleteEntries` gelöscht (K vor dem Befehl), `copyEntries` kopiert. Sonst: `copyEntryToDates` «‹Typ› «‹K›» an ‹n› Tage kopiert»; `setDayColumnSet` «Spaltensatz «‹Name›» zugewiesen»; `setDayDisplay` «Darstellung «voll|kompakt|ausgeblendet» gesetzt»; `updateColumnSet` «Spaltensatz «‹Name nachher›» geändert»; `addTimeWindow` «Zeitfenster hinzugefügt»; `updateTimeWindow` «Zeitfenster geändert» bzw. bei Umwandlung «Beso «‹K›» in Ganztägige Bemerkung umgewandelt»; `removeTimeWindow` «Zeitfenster gelöscht»; `setBesoNumberFixed` «Nr ‹n› fixiert» bzw. «Nr ‹n› gelöst» (n nachher, sonst «–»); `renumberDay` «‹Wochentag lang› ‹dd.mm.yyyy› neu nummeriert».

## 2 Befehle

Gemeinsam: `ids` ohne Doppel (erstes Vorkommen zählt), Reihenfolge = Eingabereihenfolge; leer → `emptySelection`; unbekannte ID → `notFound` (`entryId`). Neue IDs in dieser Reihenfolge: je Eintrag zuerst `e`, dann seine Zeitfenster `t` in Fensterreihenfolge; `createdSeq` in derselben Reihenfolge. Titel von Block, Querbalken und Beso, die ein Befehl setzt, laufen durch `linkBesoRefs` (Plan vor dem Befehl, Datum nach dem Befehl; Querbalken `fromDate`) [B R-5.3-11].

## 3 Nummerierung (`numbering.ts`, rein)

```ts
export interface NumberRange { readonly min: number; readonly max: number }
export type NumberingMode = 'auto' | 'renumber';
export function numberRange(weekday: Weekday): NumberRange;   // Mo 10–19, Di 20–29, Mi 30–39, Do 40–49, Fr 50–59, Sa 60–69, So 70–79 [B R-5.3-02]
export function assignNumbers(plan: Plan, date: IsoDate, mode: NumberingMode = 'auto'): ReadonlyMap<Id, number | null>;
```

`assignNumbers` liefert für **jeden** Beso mit `date` = Datum (jeder Status) seine Nummer:
- **Sortierreihenfolge**: kleinste `sortTime` über die Zeitfenster, dann `createdSeq`, dann `id`. Kreis K = `numberRange(weekdayOf(date))`.
- **Gehalten** (behält seine Nummer, auch ausserhalb von K und auch, wenn eine andere Woche oder ein verschobener Beso dieselbe Nummer trägt, Abschnitt 8 O-2): `besoNumber ≠ null` und – im Modus `'auto'` vor dem ersten Stand (`plan.stand = null`) sowie im Modus `'renumber'` – `numberFixed` oder `status 'cancelled'` [B R-5.3-05, R-5.3-09]; im Modus `'auto'` ab dem ersten Stand jeder Beso mit Nummer [B R-5.3-06, R-14.4-02]. Belegt = Nummern gehaltener Beso in K.
- **Vor dem Stand und `'renumber'`**: die übrigen Beso erhalten in Sortierreihenfolge die freien Nummern von K aufsteigend; reichen sie nicht, `null` [B R-5.3-03, F-13, F-14].
- **Ab dem Stand (`'auto'`)**: die übrigen (= ohne Nummer) erhalten in Sortierreihenfolge je die kleinste freie Nummer grösser als die höchste belegte, sonst die kleinste freie in K, sonst `null`; jede vergebene gilt sofort als belegt [B R-5.3-07, R-5.3-09, F-13, F-52; P V-03-8 auch, wenn die Nummer erst später frei wird, z.B. durch Löschen].
