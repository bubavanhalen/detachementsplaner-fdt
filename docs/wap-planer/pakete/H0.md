## Schnittstelle der Harness-Skripte (vom Orchestrator festgelegt, da Schritt 2 entfällt)

Alle Skripte: Node ≥ 24, ESM (`.mjs`), keine Abhängigkeiten ausser Node-Standardbibliothek und `git`. Meldungen Deutsch. Exit-Code 0 = in Ordnung, 1 = Verstoss oder Bedienfehler, 2 = Blockierung (nur Hook). Kein Skript gibt gefundene Personendaten im Klartext aus (Treffer maskiert, z.B. `756.****.****.**`, nur Art, Datei und Zeile).

1. **`docs/wap-planer/test-lock.json`**: `{ "version": 1, "files": { "<Pfad relativ zur Worktree-Wurzel, mit />": "<sha256 hex, klein>" } }`. Nur Dateien, keine Muster. Einträge sortiert. Hashes über den Dateiinhalt mit normalisierten Zeilenenden (CRLF → LF), damit `core.autocrlf` keine Fehlalarme erzeugt.
2. **Hook `scripts/wap/guard-edit.mjs`** (Claude-Code-`PreToolUse`, Matcher `Edit|Write|MultiEdit|NotebookEdit`): liest das Hook-JSON von stdin (`tool_name`, `tool_input.file_path` bzw. `notebook_path`). Ermittelt den Worktree der Zieldatei über `git -C <nächstes existierendes Elternverzeichnis> rev-parse --show-toplevel`. Hat dieser Worktree keine `docs/wap-planer/test-lock.json` → erlauben (Exit 0; übrige Suite unberührt, R-H-08). Sonst blockieren (Exit 2, Grund auf stderr mit Hinweis auf `lock-update`), wenn der Pfad (Gross/Klein und `\`/`/` normalisiert, auch über `..` und absolute Pfade) in `files` steht oder `docs/wap-planer/test-lock.json` selbst ist. Ungültiges JSON in stdin oder in `test-lock.json` → blockieren (sicherer Zustand).
3. **`scripts/wap/lock-check.mjs [--root <verz>]`** (Standard: Worktree des aktuellen Verzeichnisses): prüft alle Einträge; meldet je Abweichung `geändert` oder `fehlt` mit Pfad; Exit 1 bei mindestens einer Abweichung oder fehlender `test-lock.json` auf einem WAP-Zweig; Ausgabe `Lock-Prüfung: N Dateien in Ordnung` bei Erfolg.
4. **`scripts/wap/lock-update.mjs --grund "<Text>" [--befund <ID>] (--add <pfad>… | --remove <pfad>… | --refresh <pfad>… | --refresh-all)`**: ohne `--grund` (nicht leer) Exit 1 ohne Änderung. `--add` sperrt neue Dateien (müssen existieren), `--remove` entsperrt, `--refresh` übernimmt den aktuellen Hash gesperrter Dateien. Schreibt `test-lock.json` und hängt an die Tabelle «Protokoll `test-lock.json`» in `docs/wap-planer/FINDINGS.md` eine Zeile an: `| dd.mm.yyyy | <HEAD kurz> | <pfade, kommagetrennt> | <Aktion>: <Grund> | <Befund-ID oder –> |`. Nur der Orchestrator führt es aus (Regel, nicht technisch erzwungen).
5. **`scripts/wap/privacy-scan.mjs (--staged | <pfad>…)`**: prüft bei `--staged` die gestagten Inhalte (`git diff --cached --name-only --diff-filter=ACMR` und `git show :<pfad>`), sonst die genannten Dateien/Verzeichnisse (rekursiv, ohne `node_modules`, `.git`, `dist`, `coverage`, `spikes`, `.qa`, `reference`). Blockiert: jeden Pfad unter `reference/` (gestagt oder genannt), AHV-Nummern `756\.\d{4}\.\d{4}\.\d{2}`, Schweizer Telefonnummern (`+41`/`0041`/`0` + 9 Ziffern, mit Leerzeichen/Punkten/Strichen gegliedert oder ungegliedert), E-Mail-Adressen, Namen aus der Sperrliste (ganze Wörter, Gross/Klein egal). Sperrliste: `$WAP_REFERENCE_DIR/datenschutz-sperrliste.txt`, sonst `<Haupt-Checkout>/reference/datenschutz-sperrliste.txt` (Haupt-Checkout = Elternverzeichnis von `git rev-parse --git-common-dir`); eine Zeile pro Name, `#` = Kommentar. Fehlt sie → Exit 1 mit Meldung. Binärdateien: nur Pfadprüfung. Ausnahmen: E-Mail-Adresse `noreply@anthropic.com` (Commit-Trailer) und Adressen in einer versionierten Positivliste `scripts/wap/privacy-allow.txt` (feste Zeichenketten). Tests erzeugen verbotene Muster zur Laufzeit (z.B. per Verkettung), damit der Testcode selbst den Scan besteht.
6. **Commit-Hook**: `scripts/wap/pre-commit.mjs` führt `lock-check` und `privacy-scan --staged` aus. `scripts/wap/install-hooks.mjs` installiert in `<git-common-dir>/hooks/pre-commit` einen kleinen Shell-Shim, der nur auf Zweigen `wap-planer` und `wap/*` und nur wenn `scripts/wap/pre-commit.mjs` im aktuellen Worktree existiert, dieses mit `node` ausführt, sonst Exit 0. Ein vorhandener fremder `pre-commit`-Hook wird nicht überschrieben (Exit 1 mit Meldung); ein eigener (erkennbar an einer Kennzeile) wird aktualisiert.
7. **Hook-Konfiguration** in `.claude/settings.json` (`hooks.PreToolUse`) ruft `node "$CLAUDE_PROJECT_DIR/scripts/wap/guard-edit.mjs"` auf. Nach dem Merge von H0 sperrt der Orchestrator per `lock-update --add` mindestens: `scripts/wap/*` (jede Datei einzeln), `.claude/settings.json`, `docs/wap-planer/pakete/H0.md` nicht (Checkliste bleibt beschreibbar).
8. **Tests** unter `tests/wap-harness/*.test.ts` (Vitest, Umgebung `node`), jeder Testname mit ID `[R-H-nn]`; sie arbeiten in temporären Git-Repos/Worktrees (`os.tmpdir()`), nie im Arbeits-Checkout.
